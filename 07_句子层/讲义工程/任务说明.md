# 讲义工程 · 给 Claude Code（Opus）的任务说明

## 这件事是为了什么

委托人在备考广东申论，写作底子弱。前面已经把十二篇定稿大作文和十二套小题逐句对回了材料（`07_句子层/out/`），又把当天讨论的全部方法和这些数据合成了一份理论稿（`07_句子层/讲义工程/理论全量稿.md`）。

那份理论稿为了不丢信息，用了压缩记法，没有例子，读起来像提纲。委托人要的是一份他自己能读懂、能照着练的讲义。你的任务两个词：**说人话，详细**。

1. 把理论稿逐条翻成大白话。
2. 给每条理论配上足够多、挑过的例子。例子里要有材料原文和改写后的句子，层层展开，既能当讲解，也能当练习（先只看原文自己改，再展开看成品）。

读者画像：语文基础不好，逻辑好，喜欢先懂道理再看例子。他会反复翻这份讲义，也会拿例子当题做。所以道理要讲透，例子要准、要挑。

## 输入

| 东西 | 在哪 |
|---|---|
| 理论稿（唯一的理论来源，编号就是讲义的编号） | `07_句子层/讲义工程/理论全量稿.md` |
| 十二个样本：材料、定稿大作文、定稿小题答案 | `07_句子层/samples/<样本>/material.txt、essay.txt、q12.txt` |
| 已有的逐句匹配数据，当例子的候选池 | `07_句子层/out/<样本>/clauses.jsonl、q12.jsonl、card.json`，和 `out/汇总.md` |
| 两份早期手册，里面有不少现成的「原句→成品」对照 | `07_句子层/参考/` |
| 工具 | `07_句子层/讲义工程/tools/verify_examples.py`、`render.py` |
| 格式和质量的示范 | `07_句子层/讲义工程/data/示范_二转译.json` 以及它渲染出来的 `out/示范_二转译.md` |

样本只用这十二个定稿。真人卷合集不读。机构参考答案只在一处用：理论稿三.3 标了「机构」的两种写法（依据式、反面式），例子从 `2025…省市卷·参考答案.pdf` 和 `2023…县级卷·参考答案.pdf` 的范文里取，取的时候在例子标题里注明「机构范文」，并把 `product_is_mine` 设为 true 以跳过定稿核对。`2024…三卷行政执法` 仍然不许碰。不要改动 `01_方法/` 到 `06_历史过程/` 以及 `07_句子层/out/` 里的任何文件。

## 产出

数据和成品分开。你写的是数据，成品由脚本生成。

```
07_句子层/讲义工程/
    data/0_总前提.json  1_写作思路.json  2_转译.json  3_自造词.json  4_节奏.json  5_小题.json  6_考前理解.json  7_整合.json
    out/（同名的 .md 和 .opml，由 render.py 生成）
    存疑清单.md
```

- `.md` 是标题加层层缩进的列表，在 Obsidian、VS Code、Logseq 里标题和列表项都能折叠。
- `.opml` 是大纲文件，幕布、XMind、MindNode、OmniOutliner 都能导入，一层一层点开。
- **不要产出 HTML，数据里也不要写任何 HTML 标签**（包括 `<details>`、`<br>`、`<b>`）。强调只用脚本自动加的粗体。
- 做完后删掉 `data/示范_二转译.json` 和它的两个渲染文件。

### 数据结构

每个 json 文件一个部分：

```json
{
  "part": "二",
  "title": "转译：材料句怎么变成文章句",
  "intro": "这一部分开头的几句话（可空）",
  "nodes": [ 节点, 节点, … ]
}
```

节点（和理论稿的编号一一对应，可以嵌套）：

```json
{
  "id": "二.2 第8行",
  "title": "用大白话写的小标题",
  "min_examples": 10,
  "one_line": "一句话版，四十字以内",
  "plain": ["讲开了说，第一段", "第二段", "……"],
  "examples": [ 例子, … ],
  "usages":   [ 用法, … ],
  "children": [ 子节点, … ]
}
```

例子有两种形状，二选一。

单句的例子（一句或几句材料原文，变成定稿里的一句）：

```json
{
  "tag": "典型／变体／难点／反例",
  "title": "这条例子看什么（十来个字）",
  "sample": "2025选调",
  "where": "第三段长句",
  "source": [
    {"material": "二", "text": "完整的材料原句，一字不差", "kept": ["留下来的片段", "……"]}
  ],
  "product": "定稿里的那一句，一字不差",
  "steps": "动了什么：圈了什么、划了什么、删了什么、加了什么字",
  "why": "为什么选它、它比前面几条多教了什么"
}
```

整段的例子（开头、结尾、一个完整中间段、一道小题的整份答案）：把定稿按拍子切开，每一截下面挂它的材料出处。

```json
{
  "tag": "典型", "title": "……", "sample": "2025选调", "where": "开头",
  "parts": [
    {"label": "高帽", "text": "定稿里的这一截，一字不差",
     "source": [{"material": "二", "text": "完整的材料原句", "kept": ["……"]}],
     "note": "这一截怎么来的、起什么作用"}
  ],
  "why": "……"
}
```

用法（给「要积累的词和句框」用，展示定稿里是怎么用这个词的）：

```json
{"sample": "2025选调", "where": "第三段长句", "sentence": "定稿或小题答案里的原句", "focus": "让", "note": "前面是什么、后面接了什么"}
```

几条规矩：

- `source.text` 要给**完整的原句**，必要时连着的两三句都给，让读者只看原文就能动手改。`out/*/clauses.jsonl` 里的 `quote` 只是一小截，必须回到 `material.txt` 把整句取出来。
- `kept` 列出原文里被留下来的片段，脚本会把它们加粗。片段必须是原文里连续的字。
- 原文来自定稿本身时（比如拿开头的一句对结尾回收它的那一句），给 `source` 加 `"from": "essay"`。
- 理论稿二.4「不学的高成本写法」要给出低成本的替代写法，这种替代句是你照规则写的，不在定稿里：把 `product_is_mine` 设为 true，脚本会标成「示范」。除了二.4 和上面说的机构范文，别处不要用它。
- `min_examples` 按下文的配例表填，核对脚本会列出没达标的节点。

## 第一件事：转人话

对象是理论稿的〇到七。附录的对账表不用转，它是给你核对用的清单：转完后逐行对一遍，确认左边每个话题在讲义里都找得到。

1. **编号、结构、意思不动。** 不增理论，不删理论，不调顺序。你觉得理论和数据对不上、或者哪句话你拿不准意思的地方，原样转写，同时记进 `存疑清单.md`（写明编号、原话、你的疑问、数据里的证据），不要自己改。
2. **记法全部展开。** 理论稿〇.4 的记法表只在理论稿里有效。讲义里不出现「甲乙丙丁」「材一」「标、理、长、收」这类缩写，不出现箭头，不出现「7/12」「29/48」这种写法（写成「十二篇里有七篇」「四十八个中间段里有二十九段」）。
3. **句框是例外，但要写开。** 句框必须留空位，空位用方括号加一个说得明白的词，比如［广东自己提过的目标］，不要用［甲］。每个句框后面必须跟着填好的真实例子。
4. **用当天的叫法。** 理论稿〇.5 左边那一列：爷爷的话、高帽、点难、总论点、标签句、道理句、长句、收束句、点名、落点、评价。每个叫法第一次出现时用一句话解释。语法术语尽量不用，用了就解释（比如「动宾短语」写成「一个动词加它管的东西，比如“推动科技创新”」）。
5. **每个节点两层。** `one_line` 是一句话版，四十字以内，说清「这条要你干什么」。`plain` 是讲开了说，二到五段，每段三四句，顺序是：这是什么 → 为什么管用（从阅卷人怎么读、或者从爷爷爸爸儿子的关系上讲）→ 具体怎么做 → 做不到时怎么退一步。
6. **口气。** 对读者称「你」，整句话，不用提纲式的短语。不写「值得注意的是」「需要指出」这类空话。不提这份讲义是怎么来的，不提模型、对话、拟合过程；数据只以「十二篇定稿里」的口吻出现。
7. 理论稿里的 `【例→……】` 是给你的找例子指向，不进讲义。

### 怎么挑、怎么排

例子按优先级排，不是按出现顺序排。脚本会按 `tag` 排：典型 → 变体 → 难点 → 反例。同一档里你自己排好先后。

- **典型**：这条规则最干净的样子，原文到成品几乎只有这条规则在起作用。放最前面。
- **变体**：同一条规则的不同长相（名字有几个、评价在句首还是句尾、原文跨不跨段）。每条变体要和前面的不一样，`why` 里写明不一样在哪。
- **难点**：容易做错的。评价不在本段、评价说的是某个人、两处拼接、要换层级词、一个例子有两句评价要挑。
- **反例**：定稿里没做好的地方（只有事实没有评价的分句、开头点了难后文没接的、引号里的字和材料不一致的）。数量少，有就列。

挑的标准：

- 每条例子都要比前面几条多教一点东西。教不出新东西的不要，宁可少于目标数，并在 `存疑清单.md` 里说明这个节点为什么不足。
- 同一个节点里，同一篇定稿的例子不超过三条（天然全集的节点除外）。
- 近几年的卷子（2023 到 2026）优先。
- 原文和成品的对应要一眼看得出来。对应关系要解释半天的，归到难点，不要放在前面。

### 每条例子里写什么

- `steps` 用读者做题时的动作来写：圈了哪几个字、划了哪半句、删了哪几类东西、加了哪个字。不要写「运用了某某手法」。
- `why` 一两句话。
- 整段例子的 `note` 写这一截「怎么来的」和「在这里起什么作用」两件事。

## 核对和渲染

```
python 07_句子层/讲义工程/tools/verify_examples.py "07_句子层/讲义工程/data/*.json"
python 07_句子层/讲义工程/tools/render.py
```

- 核对必须全部通过：每段原文在材料里一字不差，每个留下来的片段在原文里，每句成品和用法在定稿或小题答案里。找不到就回去重新取，不要凭印象写。
- 核对脚本会列出例子数低于 `min_examples` 的节点。做完时这张单子要么是空的，要么每一条都在 `存疑清单.md` 里有解释。
- 每做完一个部分就核对、渲染、提交一次。

## 工作顺序

1. 八个部分的人话全部转完（只填 `one_line` 和 `plain`，`examples` 先空着），渲染出来。这一步先提交，委托人可以先读。
2. 配例子，按这个顺序：二（转译）→ 一（写作思路）→ 三（自造词）→ 五（小题）→ 四（节奏）→ 七（整合）→ 〇。第六部分不配例子。
3. 对账：拿理论稿附录的对账表逐行核对讲义；写 `存疑清单.md`；删掉示范文件。

## 容易出错的地方

- **凭印象写原文。** 定稿读起来像材料，很容易顺手写一个「原文」。所有原文回 `material.txt` 复制。
- **原文给得太短。** 只给匹配上的那一小截，读者没法拿它当练习。给完整的句子。
- **例子平铺。** 把原文、成品、讲解写进同一段话里。必须分层，放进各自的字段。
- **凑数。** 同一种长相的例子堆十条。宁缺毋滥。
- **理论走样。** 转人话时顺手「优化」了理论，或者把几条并成一条。不许。
- **缩写回潮。** 写到后面又开始用甲乙、箭头、分数式。交付前全文搜一遍「甲」「→」「/12」「/48」。
- **后半截变薄。** 前两个部分写得细，后面越写越短。每个节点的 `plain` 都要达到同样的详细程度，最后通读一遍，专门检查三、四、五。
- **HTML 标签。** 数据里不要出现尖括号标签。

## 不要做的事
