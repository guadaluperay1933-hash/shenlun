# 每道题的交付文件格式（<set_id>/Qn.md）

这份文件会原样排进 PDF，只写给考生看的东西：答案、怎么想的、为什么这么写。对照真人卷、对照上一版、账本编号这些过程记录不进这里（放 过程.md）。不写任何 HTML 标签。

```
# 问题一　<题干的短说法>（20 分，≤200 字）

## 答案

<能直接抄到答题卡上的答案，含标点，程序核数不超上限>

## 考场上的思路

<第一人称，按真实顺序：先看题干抓了什么词、轴是什么；扫指定材料时每段是什么事；
哪几件事是一件事、为什么并；哪里犹豫过、最后为什么这么定；字数怎么分。写成两三段话，不列表。>

## 逐条解析

### 要点一　<这一条的标签>

**现实里是一件什么事**　<谁、对谁、通过什么办法、想解决什么。落到事，不许用类名了事。
只准材料能推出来的，或写明「常识」的通用机制，不编具体事实。>

**为什么归成这一条**　<并了哪几件事、它们现实里为什么是同一件事；
反例：如果……就不能并。为什么不并进相邻那一条。标签词从哪来、为什么用它。>

#### 「<答案里的一个分句>」
- 来源：材料X第N段第M句「材料原句，删节处用……」
- 怎么改的：删 / 并 / 缩 / 换 / 补动词，具体删了什么
- 为什么这么改：先说公文为什么这么写（这句话在政府文件里起什么作用），再说批卷人找的是什么
- 不这么写会怎样：<具体后果；是推测就写推测>
- 以后遇到：<一句能搬到别的题的做法>

#### 「<下一个分句>」
- ……

### 要点二　……

## 压缩与成本

<材料里这几段一共多少字，答案多少字；按什么顺序砍的（先砍什么后砍什么）；
哪些低频词特意留了、为什么；全题自造几个字、是哪几个、为什么非造不可。>
```

要求：答案里每个分句都要在逐条解析里出现一次；「现实里是一件什么事」每个要点都要有，不少于 30 字，写清谁对谁做什么；段号、句号按 `tools/pool.py` 打印的编号，引原句要一字不差。
